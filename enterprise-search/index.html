Enterprise RAG & Intelligent Document Search

Processing 5+ Million Pages with On-Premise AI: From High-Speed OCR to Domain-Specific Knowledge Retrieval

The Challenge: Industrial Scale & Data Sovereignty

In large industrial organizations like PetroPars, critical knowledge is trapped in millions of unstructured documents (PDFs, scanned forms, technical manuals). Generic cloud solutions pose two major risks: Data Privacy and Cost Scalability. The goal was to build a sovereign, on-premise platform capable of ingesting, indexing, and retrieving information from over 5 million pages while maintaining strict access controls and domain-specific accuracy.

This project implements a full-stack Retrieval-Augmented Generation (RAG) pipeline combined with a high-performance OCR engine, designed to handle Persian/English bilingual documents and complex engineering layouts.

High-Performance OCR Pipeline

The foundation of the search engine is a custom OCR pipeline optimized for speed and accuracy using Qwen3.6-35B-A3B via llama.cpp. We selected the 35B parameter model because it fits entirely within 32GB VRAM, while its Mixture-of-Experts (MoE) architecture activates only 3B parameters per token, delivering inference speeds comparable to much smaller models without sacrificing reasoning capabilities.

Performance Tuning & Inference Configuration

Achieving sub-second latency at this scale required meticulous low-level optimization of the inference engine. Below is the production-grade configuration used for our primary Qwen3.6-35B-A3B instance: 

.\llama-server -m "Qwen3.6-35B-A3B-UD-Q4_K_M.gguf" \
  -mm "mmproj-Qwen3.6-35B-A3B-UD-Q4_K_M.gguf" \
  -c 8192 -ctk q8_0 -ctv q8_0 --no-mmap \
  --host 0.0.0.0 --port 8085 -rea off -ngl -1 -t 16

Key Optimizations Explained:

  • -ctk q8_0 -ctv q8_0: Quantizing Key/Value cache to 8-bit reduces VRAM footprint by ~50% with negligible accuracy loss, allowing larger context windows.
  • --no-mmap: Disabling memory mapping forces full pre-loading into VRAM, eliminating OS paging overhead during high-concurrency inference.
  • -ngl -1: Full GPU offloading ensures zero CPU-GPU data transfer bottlenecks during token generation.
  • -t 16: Thread count tuned to match physical core availability for optimal prompt processing parallelism.
  • -rea off: Disabling rope embedding scaling for native MoE compatibility and stable long-context performance.

System Architecture & Data Flow

A high-level overview of the end-to-end pipeline, from raw document ingestion to context-aware response generation.

RAG Architecture & "Deep Search"

The system uses Elasticsearch for vector storage and retrieval, powered by infinity-emb for embeddings. A key innovation is the "Deep Search" fallback mechanism: if the initial Persian embedding search yields low confidence, the query is automatically translated to English and re-executed against the index to ensure comprehensive coverage.

  • Multi-Model LLM Server: A unified llama.cpp server hosts multiple specialized models. Lightweight models handle translation, classification, and title generation, while the heavy 35B model focuses solely on answer synthesis.
  • Domain-Aware Routing: If a user doesn't specify a category (e.g., ICT, SAP), the system auto-classifies the query and routes it to the correct Elasticsearch index and prompt template.
  • Dynamic Prompt Engineering: Admins can define versioned prompts and map them to specific domains, enforcing behavioral constraints and output formats.

Key Features Demonstrated

1. Granular Access Control & Cost Management

As an enterprise tool, the system includes a comprehensive admin dashboard for managing users, setting daily token caps, and defining Role-Based Access Control (RBAC). Users are restricted to specific knowledge domains (e.g., ICT, HR, SAP) to prevent data leakage across departments.

2. Multimodal & Visual Reasoning

Beyond text, the system supports vision-language tasks. Users can upload screenshots (e.g., of an error message or UI) and ask questions like "Which button should I click?". The model analyzes the image contextually and provides precise guidance.

3. Dynamic Visualization (Mermaid.js)

The LLM can generate Mermaid flowcharts on-the-fly to visualize complex processes. For example, when asked about software installation, it renders an interactive flowchart showing steps from "Check Requirements" to "Final Verification", enhancing comprehension significantly.

4. Hybrid Inference Strategy

The system intelligently balances security and speed:

  • Secure Mode: Sensitive queries run on local CUDA GPUs (On-Premise) ensuring data never leaves the infrastructure.
  • Fast Mode: Non-sensitive queries are routed to Cloud APIs for near-instant latency with zero local GPU load.

Future Roadmap & Strategic Enhancements

With the core RAG and OCR infrastructure established, the next phase focuses on interoperability, advanced reasoning, and autonomous agent capabilities:

  • MCP (Model Context Protocol) Integration: Transitioning from a monolithic chat interface to an MCP-compliant server architecture. This will allow the AI to securely connect with external tools (IDEs, databases, CI/CD pipelines) as standardized resources, enabling true agentic workflows beyond simple Q&A.
  • GraphRAG Implementation: Moving beyond vector similarity to knowledge graphs. By extracting entities and relationships from the 5M+ page corpus, we can answer complex multi-hop questions that pure embedding search struggles with.
  • Adaptive Retrieval & Re-ranking: Implementing a dynamic routing layer that chooses between keyword search (BM25), dense vector search, or hybrid approaches based on query intent.
  • Structured Output Enforcement: Integrating JSON-mode and grammar-constrained decoding to ensure the LLM always returns parseable data for downstream automation.
  • Real-time Feedback Loop: Leveraging the existing like/dislike system to create an active learning pipeline where negative feedback triggers automated review queues.
