Enterprise RAG & Intelligent Document Search

Processing 5+ Million Pages with On-Premise AI — Measured OCR Quality (WER 2.79% / CER 2.57%), Hardware Benchmarks & Full TCO Analysis

The Challenge: Industrial Scale & Data Sovereignty

In large industrial organizations, critical knowledge is trapped in millions of unstructured documents (PDFs, scanned forms, technical manuals). Generic cloud solutions pose two major risks: Data Privacy and Cost Scalability. The goal was to build a sovereign, on-premise platform capable of ingesting, indexing, and retrieving information from over 5 million pages while maintaining strict access controls and domain-specific accuracy.

This project implements a full-stack Retrieval-Augmented Generation (RAG) pipeline combined with a high-performance OCR engine designed for Persian/English bilingual documents and complex engineering layouts (tables, multi-column datasheets, noisy historical scans).

High-Performance OCR Pipeline & Measured Quality Metrics

The foundation of the search engine is a custom OCR pipeline optimized for speed and accuracy using Qwen3.6-35B-A3B (Mixture-of-Experts) via llama.cpp. The 35B-parameter model fits in 32 GB VRAM; its MoE architecture activates only ~3B parameters per token, delivering inference speeds comparable to much smaller models without sacrificing reasoning quality on complex layouts.

Pre-OCR Orientation & Scan Quality Optimization (150 DPI)

Prior to running deep OCR, each scanned page undergoes automatic rotation analysis using pytesseract.image_to_osd to detect and correct orientation angles.

For A4 scanned document inputs, scanning at 150 DPI provided the optimal trade-off between throughput and accuracy: 300 DPI caused severe speed degradation and high computational cost, whereas 100 DPI failed to provide sufficient text clarity for dense Persian/English layouts. 

def detect_orientation(image_path: str) -> int:
    """تشخیص زاویه چرخش با Tesseract OSD"""
    try:
        img = cv2.imread(str(image_path))
        if img is None:
            return 0
        osd_data = pytesseract.image_to_osd(img)
        for line in osd_data.split('\n'):
            if 'Rotate' in line:
                return int(line.split(':')[1].strip())
        return 0
    except Exception:
        return 0

Performance Tuning & Inference Configuration

Achieving production throughput required low-level optimisation of the inference engine. The configuration used for the primary Qwen3.6-35B-A3B instance: 

./llama-server \
  -m "Qwen3.6-35B-A3B-UD-Q4_K_M.gguf" \
  -mm "mmproj-Qwen3.6-35B-A3B-UD-Q4_K_M.gguf" \
  -c 8192 -ctk q8_0 -ctv q8_0 --no-mmap \
  --image-min-tokens 1024 \
  --host 0.0.0.0 --port 8085 \
  -rea off -ngl -1 -t 16

Key Optimisations:

  • -ctk q8_0 -ctv q8_0 — KV-cache quantisation to 8-bit reduces VRAM footprint by ~50% with negligible accuracy loss.
  • --no-mmap — Forces full model preload into VRAM, eliminating OS paging under high concurrency.
  • -ngl -1 — Full GPU offload; zero CPU–GPU transfer during generation.
  • -t 16 — Thread count matched to physical cores.
  • -rea off — Disables rope scaling for native MoE compatibility.
  • --image-min-tokens 1024 — Sufficient visual tokens for complex multi-column tables.

System Architecture & Data Flow (RAG Layer)

RAG Architecture & “Deep Search”

Due to the lack of input data segmentation across raw sources, the initial 5 million pages were directed to the high-throughput search engine. Subsequently, higher-quality, structured documents (Word and native PDF files with 100% human verification) were directed to the RAG processing pipeline.

During RAG processing, each text chunk is evaluated relative to its execution chain. When required, the corresponding chain information is injected into Elasticsearch as part of the document metadata to significantly enhance retrieval precision.

The system uses Elasticsearch for vector storage and retrieval, powered by infinity-emb for embeddings. A key innovation is the “Deep Search” fallback mechanism: if the initial Persian embedding search yields low confidence, the query is automatically translated to English and re-executed against the index to ensure comprehensive coverage.

  • Multi-Model LLM Server: A unified llama.cpp server hosts multiple specialised models. Lightweight models handle translation, classification and title generation; the heavy 35B model focuses on answer synthesis.
  • Domain-Aware Routing: If a user does not specify a category (e.g. ICT, SAP), the system auto-classifies the query and routes it to the correct Elasticsearch index and prompt template.
  • Dynamic Prompt Engineering: Admins can define versioned prompts and map them to specific domains, enforcing behavioural constraints and output formats.

Key Features Demonstrated

1. Granular Access Control & Cost Management

As an enterprise tool, the system includes a comprehensive admin dashboard for managing users, setting daily token caps, and defining Role-Based Access Control (RBAC). Users are restricted to specific knowledge domains (e.g. ICT, HR, SAP) to prevent data leakage across departments.

2. Multimodal & Visual Reasoning

Beyond text, the system supports vision-language tasks. Users can upload screenshots (e.g. of an error message or UI) and ask questions such as “Which button should I click?”. The model analyses the image contextually and provides precise guidance.

3. Advanced Data Analysis & Process Flowchart Generation

The RAG engine possesses robust data analysis capabilities. As demonstrated in the demo videos, the system can parse operational instructions to analyze data, extract key metrics, and dynamically generate process flowcharts and visualization diagrams (e.g., using Mermaid.js) directly from procedural documentation.

4. Hybrid Inference Strategy

The system intelligently balances security and speed:

  • Secure Mode: Sensitive queries run on local CUDA GPUs (on-premise) ensuring data never leaves the infrastructure.
  • Fast Mode: Non-sensitive queries may be routed to Cloud APIs for near-instant latency with zero local GPU load.

Future Roadmap & Strategic Enhancements

With the core RAG and OCR infrastructure established, the next phase focuses on interoperability, advanced reasoning and autonomous agent capabilities:

  • MCP (Model Context Protocol) Integration: Transitioning from a monolithic chat interface to an MCP-compliant server architecture. This will allow the AI to securely connect with external tools (IDEs, databases, CI/CD pipelines) as standardised resources, enabling true agentic workflows beyond simple Q&A.
  • GraphRAG Implementation: Moving beyond vector similarity to knowledge graphs. By extracting entities and relationships from the 5 M+ page corpus, complex multi-hop questions that pure embedding search struggles with become answerable.
  • Adaptive Retrieval & Re-ranking: A dynamic routing layer that chooses between keyword search (BM25), dense vector search or hybrid approaches based on query intent.
  • Structured Output Enforcement: Integrating JSON-mode and grammar-constrained decoding to ensure the LLM always returns parseable data for downstream automation.
  • Real-time Feedback Loop: Leveraging the existing like/dislike system to create an active-learning pipeline where negative feedback triggers automated review queues.
